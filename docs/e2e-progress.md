## Findings — real defects the suite exposed

Each open one is pinned by a `test.fail(...)` whose reason starts with `FINDING Fn`, so a
fix turns it into an unexpected pass and forces the marker off. None has been
fixed in the library: that is a separate decision.

## Observations — not defects, recorded so nobody re-derives them

| ID  | What                                                                                                                                                                                                                                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O1  | Emulated Chromium touch sends a compatibility `mousedown`/`click` after _any_ release, including a 700 ms hold, and that click ends the long-press block selection. Android and iOS send no click after a long press, so TO2 asserts the selection while the finger is down; confirm the release on hardware (plan R4). |
| O2  | `locator.click()` scrolls its target into view, and that scroll's event lands a frame after the click, closing the popover the click just opened. Use `EditorPage.clickControl` for anything that opens a popover.                                                                                                      |
| O3  | Chromium coalesces `selectionchange`: two arrow presses inside one frame that end where they started are no move to the editor. Human-paced input settles between presses (F4 test).                                                                                                                                    |
| O4  | On macOS, WebKit and Firefox follow the platform: `Home` does not move the caret. Playwright's WebKit still maps `Backspace` outside an editable field to history.back(). (An earlier note here blamed F10 on the host; it was F13.)                                                                                    |
| O5  | Each engine's async clipboard sanitises `text/html` differently (Chromium resolves relative `src` and drops `<script>`; WebKit drops closed `<details>` bodies and turns a leading space into U+00A0).                                                                                                                  |
| O6  | Animated properties (`margin-inline-start`, `padding-inline-start`, 120 ms) must be polled, not read once.                                                                                                                                                                                                              |
| O7  | Playwright's WebKit on macOS occasionally crashes the browser process mid-run (`-[NSTextInputContext textInputClientDidUpdateSelection]: unrecognized selector`). It is the browser, not a test; it has not been seen on Linux, where CI runs.                                                                          |
